# Южане · Обучение

Telegram WebApp для обучения сотрудников + кабинет менеджера.

- **Сотрудник** регистрируется (или получает логин от менеджера), входит по логину и паролю — в браузере или из Telegram-бота, читает уроки, сдаёт тесты, получает сертификат.
- **Менеджер** входит в кабинет по логину и паролю: редактирует блоки, уроки, вопросы, картинки и справочники, видит каждого сотрудника и его ответы, выгружает результаты в Excel.
- **Администратор** — всё, что менеджер, плюс назначает роли и меняет настройки.

## Роли и вход

| Роль | Где входит | Что может |
|---|---|---|
| Сотрудник | приложение (`/`) | проходить обучение, справочники |
| Менеджер | кабинет (`/admin/`) | блоки, тесты, справочники, результаты; заводить сотрудников и сбрасывать им пароли |
| Администратор | кабинет (`/admin/`) | всё, плюс роли, удаление учётных записей, настройки |

- Первый вход в кабинет: логин **admin**, пароль **admin**. Сразу после входа система требует задать свой пароль — до этого кабинет не открывается.
- Галочка «Не выходить» хранит вход 30 дней, без неё — до закрытия вкладки (не дольше 12 часов).
- Пароли хранятся только в виде хэша PBKDF2 с солью. После 5 неверных паролей подряд вход в учётную запись блокируется на 5 минут.
- Смена пароля или роли завершает все прежние сессии этого человека.
- Регистрацию можно выключить: **Настройки → «Разрешить сотрудникам регистрироваться самим»**.

## Как устроено

```
docs/            → GitHub Pages (статический фронтенд)
  index.html       приложение сотрудника
  admin/           кабинет менеджера
  config.js        адрес API  ← поменять после деплоя
worker/          → Cloudflare Worker (API)
  src/index.js     API, учётные записи и роли, вебхук бота
  schema.sql       схема базы D1
wrangler.toml    настройки Worker
```

GitHub Pages умеет отдавать только статические файлы — базу данных и секретный токен бота там держать нельзя. Поэтому API живёт на **Cloudflare Workers** (бесплатный тариф: 100 000 запросов в день, не засыпает), данные — в **D1** (SQLite), картинки — в **KV**.

## Развёртывание

Понадобятся: аккаунт GitHub, аккаунт Cloudflare (бесплатный), Node.js 18+.

### 1. Бот

1. В [@BotFather](https://t.me/BotFather) создайте бота (`/newbot`) и сохраните токен.
2. Узнайте свой Telegram ID — например, у [@userinfobot](https://t.me/userinfobot). Он нужен только для уведомлений о результатах.

### 2. API на Cloudflare

```bash
npm install
npx wrangler login
npx wrangler d1 create yuzhane
npx wrangler kv namespace create IMAGES
```

Скопируйте `database_id` и `id` из вывода команд в `wrangler.toml`. Там же укажите:

- `WEBAPP_URL` — адрес GitHub Pages, например `https://ivanov.github.io/yuzhane`
- `ADMIN_IDS` — Telegram ID, куда бот присылает результаты тестов (через запятую)

Задайте токен бота (значение вводится после команды):

```bash
npx wrangler secret put BOT_TOKEN
```

Создайте таблицы и опубликуйте Worker:

```bash
npm run db:init
npm run deploy
```

В конце появится адрес вида `https://yuzhane-api.<ваш-поддомен>.workers.dev`.

### 3. Фронтенд на GitHub Pages

1. Впишите адрес Worker в `docs/config.js`.
2. Загрузите проект в репозиторий GitHub.
3. В репозитории: **Settings → Pages → Build and deployment → Deploy from a branch**, ветка `main`, папка `/docs`.

### 4. Последние шаги

1. Откройте `https://ivanov.github.io/yuzhane/admin/`, войдите как **admin / admin** и задайте свой пароль.
2. **Настройки → «Настроить бота»** — подключит вебхук, кнопку «Обучение» в меню и команды `/start`, `/admin`.
4. По желанию: **Настройки → Импорт из Google Таблицы** — перенесёт контент из старой таблицы.

Назначить менеджера: **Сотрудники** → карточка человека → **Роль**. Завести учётную запись вручную: **Сотрудники → «Добавить»**.

### Переход со старой версии (вход через Telegram)

```bash
npx wrangler d1 execute yuzhane --remote --file=worker/migrate-v2.sql
npm run db:init
```

Миграция удаляет старые Telegram-профили и их попытки — привязать их к учётным записям не к чему.

## Локальная разработка

```bash
npm install
npx wrangler d1 execute yuzhane --local --file=worker/schema.sql
npx wrangler dev          # API на http://localhost:8787
npm run web               # фронтенд на http://localhost:5500
```

Файл `.dev.vars` с `DEV_MODE=1` разрешает запросы к локальному API со страниц на `localhost`. Он не попадает в git и не используется при деплое.

> На Windows при очень длинном пути к проекту локальная база может не открыться (`SQLITE_CANTOPEN`). Добавьте к командам `--persist-to C:\yz-db`.

## Безопасность

- Правильные ответы не отправляются в приложение заранее: сервер проверяет каждый ответ, засчитывает только первый и сам считает итог.
- Кабинет доступен только учётным записям с ролью «Менеджер» или «Администратор»; права проверяет сервер при каждом запросе.
- История попыток хранит тексты вопросов и ответов на момент прохождения, поэтому правка или удаление вопросов её не ломает.
